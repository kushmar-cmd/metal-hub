FMEA — Failure Mode and Effects Analysis

A complete interactive FMEA guide: RPN calculator, Severity/Occurrence/Detection ratings, a sample FMEA table, DFMEA vs PFMEA, the modern AIAG-VDA Action Priority (AP) method, Fault Tree Analysis (FTA), complementary tools (Fishbone, 5-Why, Pareto, 8D), and the key FMEA standards.

🧮 RPN Calculator
—
RPN = S × O × D · Maximum = 1000 · Action threshold: RPN>100 (general) / >50 (safety)
⚠️ RPN Limitations — why AIAG-VDA 2019 dropped it
Problem 1: S=9×O=1×D=1 = RPN of just 9 — but S=9 (life-threatening!) must always be addressed; a low RPN "hides" this.
Problem 2: S=2×O=5×D=5 = RPN 50 — the same number can arise from many completely different combinations.
Problem 3: No clear breakpoints — RPN 99 vs RPN 101 aren't really different, yet a "threshold of 100" treats them differently.
The modern solution: AIAG/VDA Action Priority (AP) — see dedicated tab. High S = mandatory action, regardless of O/D!

📊 Detection (D) — ability to detect before reaching the customer
DDescriptionDetection Method
1Certain detectionPhysical Poka-Yoke — cannot assemble incorrectly
2-3High detection100% automated inspection
4-6Moderate detectionStatistical inspection (SPC), sampling
7-8Low detectionVisual inspection, operator-dependent
9-10Almost undetectableNo control, only found in the field
⚠️ Note the reversed direction! D=1 = excellent detection (good). D=10 = not detected (bad). Improving D is cheaper than improving O — but preventing is better than detecting.

DFMEA — Design FMEA
Examines the design — before the part physically exists.

Asks: How can the design itself fail? Wrong material, incorrect tolerance, unexpected load, stress concentration.

Performed by: Design engineer, during development — before production!
Output: Affects material selection, GD&T, geometry.
PFMEA — Process FMEA
Examines the manufacturing process — how the part is actually produced.

Asks: Where in the process (machining/assembly/inspection) could a failure occur? Worn tool, wrong machine setting, operator error.

Performed by: Process/manufacturing engineer, before series production starts.
Output: Affects the Control Plan, inspections, in-line Poka-Yoke.
🔗 The link between DFMEA and PFMEA
DFMEA precedes PFMEA chronologically. Critical characteristics identified in DFMEA (Key Characteristics) become mandatory control points in PFMEA. Both documents are living — updated with every design/process change and field failure.
🆕 AIAG/VDA 2019 — Action Priority (AP)
The new standard (2019) replaces the raw RPN calculation with a decision table: High / Medium / Low — based primarily on S, then O, then D.
SODAction Priority
9-104+anyHigh
9-102-35+High
9-102-31-4Medium
7-84+anyHigh
7-81-3anyMedium
1-61-31-3Low
⚠️ The key difference: S=9 with low O still comes out High — it doesn't "hide" behind a low RPN number like in the old method! This is the main reason for the switch.
High — action mandatory
A documented corrective action is required. If no action is taken, a written, reasoned justification is required.
Medium — action recommended
Action recommended at the team's discretion. Documenting the decision (act/don't act) is still required.
Low — no obligation
Can be left as-is, but continue monitoring. Doesn't mean "safe" — only that relative priority is low.
🌳 FTA — Fault Tree Analysis
▸ FTA method: from the top failure ↓ down to basic causes (Top-Down)
▸ FMEA method: from a component ↑ up to system effect (Bottom-Up)
▸ Gates: AND = both · OR = either
▸ P(AND) = P₁ × P₂ (independent)
▸ P(OR) = 1-(1-P₁)(1-P₂)
▸ MIL-STD-1629A: military/defense FMEA standard
▸ IEC 60812: civilian FMEA standard
▸ AIAG/VDA FMEA: automotive, 2019+

🌳 Sample Fault Tree — oil supply failure
Top Event: Oil supply failed
  ├─ OR ─┬─ Pump failed
        ├─ AND ─┬─ Motor failed
                └─ Backup not activated
        └─ Filter clogged
        └─ Pipeline cracked
OR gate = any single branch is enough to cause the overall failure. AND gate = both branches must occur together — true redundancy!
🐟 Fishbone / Ishikawa
Maps root causes across the 6M's: Man, Machine, Method, Material, Measurement, Environment. Systematic — doesn't get stuck on the first suspect.
❓ 5-Why
Ask "why" until you reach the true root cause — usually 5 times. Trap: "operator error" is almost never the root — why did the system allow it?
📊 Pareto Analysis
80% of problems come from 20% of causes. Focuses where to invest — by cost, not just count!
8️⃣ 8D Problem Solving
D1 Team→D2 Description→D3 Containment (24h!)→D4 Verified root cause→D5 Corrective action→D6 Implementation→D7 Systemic prevention→D8 Recognition.
